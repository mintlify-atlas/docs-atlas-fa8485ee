AutoFix is a FastAPI-powered engine that closes the gap between quality assurance and software engineering. Instead of merely *finding* bugs, AutoFix autonomously *resolves* them: it receives broken Python code alongside a plain-English specification, spins up two specialized AI agents, runs the code inside an isolated subprocess sandbox, and iterates until every generated test passes — or until the configured maximum healing iteration cap is reached.

The project follows a **Layered Service Architecture** that cleanly separates concerns across four distinct tiers: the HTTP API layer handles routing and request validation; the orchestrator layer coordinates the multi-step pipeline; the AI agent layer translates natural language requirements into test suites and code patches; and the sandbox execution layer runs `pytest` in a clean subprocess environment. This separation means each tier can be tested, replaced, or extended independently.

## Two Pipeline Modes

AutoFix ships with two pipeline entrypoints, both defined in `app/services/orchestrator.py`:

- **`run_healing_pipeline(request: HealRequest)`** — Accepts raw code and requirements in-memory. Best suited for ad-hoc healing of a single file or for API clients that supply code directly. The sandbox workspace is ephemeral and cleaned after each run.
- **`run_repo_healing_pipeline(repo_dir, language, failing_file, failing_logs)`** — Operates directly on a cloned repository directory. Uses the `RepoAnalyzer` to build an AST dependency graph, extracts context from related modules, and writes patches directly to disk before re-running the existing repository test suite.
